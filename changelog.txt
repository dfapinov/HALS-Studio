24/10/26

- Added recovery without a project JSON by opening a measurement WAV. Studio
  scans that directory for compatible coordinate filenames, reports skipped
  files, and rejects duplicate positions or mixed sample rates. Outputs are
  saved one directory above the recordings, in the usual outputs folder.

- Reuse an existing project when opening WAVs directly; otherwise create a
  project JSON after Stage 1 succeeds. Subsequent saves update the same file,
  retaining the recording directory and which metadata was unavailable.

- When no tweeter coordinate is supplied, Stage 2 estimates the HF seed using
  a 20 mm grid scan inside the measurement cylinder followed by simplex
  refinement. The scan uses an available bin at or below the end frequency,
  capped at 20 kHz. The LF search starts at (0, 0, 0), constrained to the
  cylinder. A Run message explains the fallback; the estimated tweeter is
  saved to the project for reuse and display in the Export visualisation.

- Missing RFT defaults to 5 ms for Stage 1 alpha tapering, without highlighting
  an assumed reflection-free range. Stage 3 explains its 5 ms fallback when
  Run is clicked and retains any manually chosen lower test frequency.

- Added Export IR and Export All to the Stage 1 results viewer. Export the
  selected measurement or the complete set, choosing FDW or complex-smoothed
  data when both are available. The shared IR export engine writes float WAVs
  at the saved sample rate without extra tapering, gain, or timing correction.

- Removed automatic per-file peak normalisation from WAV export to preserve
  relative measurement levels, including floating-point samples above 1.0.

- Added optional WAV set normalisation, disabled by default, with a user-set
  peak target defaulting to -6 dBFS. One gain is calculated from the loudest
  sample peak across the full set and applied to every WAV. FRD and complex
  NPZ data are unchanged; the shared gain is recorded in the export log and
  settings manifest.

Code restructuring

- Moved the application into src/hals_studio, with clearer UI, application,
  processing, analysis, persistence, and infrastructure directories.

- Clarified widget ownership by splitting large workspaces into smaller forms,
  view setup, renderers, and plotting modules. Workspaces now coordinate these
  parts rather than owning every control and drawing routine.

- Moved processing and export orchestration into application controllers, with
  explicit inputs and runtime dependencies for the numerical engine.

- Centralised worker and process-pool lifecycle, including cancellation and
  shutdown, so background work can finish without blocking the interface.

- Added versioned caches and session handling, broader pytest and pipeline
  checks, and a bundled-app self-test to protect behaviour during refactoring.

  Window labels stack near the bottom and shift to avoid traces. The plot also
  uses wheel zoom, middle-button pan, and Reset axes.

- Improved automatic SPL legend placement and panning responsiveness. Legends
  favour clear corners and open space while avoiding traces and annotations.

- Stage 2 derives its main search cylinder from the measurement coordinates in
  the NPZ filenames. Full grid re-scan XYZ bounds default to the enclosing box,
  and remain editable.

- Fixed Stage 2 speed-of-sound optimisation using the sparse frequency list
  created by the octave-resolution setting. The six probe frequencies now come
  from the full measurement bin resolution.
